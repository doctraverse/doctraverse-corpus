# Contributing to Doc Traverse Corpus

Doc Traverse Corpus is at the design stage. Workflow feedback, questions, and
small public or synthetic document examples are useful now.

## Start with an issue

[Open an issue](https://github.com/doctraverse/doctraverse-corpus/issues) describing:

- The document task and who needs the result.
- The input formats, document structure, and relevant constraints.
- The expected output and how you would check it against the source.
- Whether the workflow needs self-hosting, an API, MCP access, or a team interface.

Use examples you have the right to share. Keep confidential documents, secrets,
and personal data out of public issues.

## Code and documentation patches

Discuss a proposed patch with the maintainers before investing in implementation.
There is no runnable development environment yet.

The project is preparing an AGPL/commercial dual-licensing model. **External
code and documentation patches will not be merged until suitable contribution
terms and an acceptance process are published.** Feedback and issue discussions
remain welcome while that work is in progress.

There is no active Contributor License Agreement (CLA) to sign yet. Submitting
a pull request does not establish a separate commercial-rights agreement, and
maintainers must not infer such permission from submission alone.

## What the contribution process needs to establish

Before a patch can be merged, the maintainers need to verify:

1. **Authority to contribute.** Identify the relevant copyright holder and any
   employer or client authorization needed for the contribution.
2. **Rights for the intended licensing model.** Obtain a documented grant that
   permits the proposed AGPL and alternative commercial distribution. The
   planned approach is a contributor license grant, with contributors retaining
   ownership; the agreement is still being developed.
3. **Third-party provenance.** Identify copied or adapted material, dependencies,
   upstream revisions, licenses, and required notices.
4. **Acceptance evidence.** Record the agreement version and acceptance against
   the contributor identity and relevant pull request or commits.

A DCO sign-off can document contribution provenance. It does not on its own
create the additional permission needed for proprietary relicensing of an
AGPL-only contribution.

Contributors remain responsible for reviewing material produced with AI tools
and for identifying its sources and applicable rights. AI assistance is not
evidence that a contribution is free of third-party restrictions.
